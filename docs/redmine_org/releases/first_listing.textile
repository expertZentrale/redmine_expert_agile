h3. redmine_expert_agile 0.2.1 — 2026-08-19

h4. Fixed

* *Cards could not be reordered inside the "New" column.* A card dropped between two others jumped to the top of the column instead of staying where it was dropped, and only that column was affected. A card gets its rank when it is dragged, so the column issues are created in is the one column that holds nothing but unranked cards — and a card dropped between two of those had no two ranks to fall between. The cards above the drop point are now ranked first, in the order they are already displayed in, before the card is placed between them. Only those: a drop near the top of a column of thousands touches a handful of rows, and the cards below it keep their place. The backlog planner, which plans the same never-dragged issues, is fixed with it.
* *Two cards dropped into the same spot could take the same rank.* Anything dropped below the last ranked card in a column was ranked one step below that card, so a second drop into the same spot repeated the rank of the first and the order between them fell back to issue id. The rank is now measured against the whole column.

h4. Upgrade notes

No migrations. Replace the plugin directory and restart.

Columns that already hold dragged cards were never affected and keep the order they have. Nothing is rewritten on upgrade: the first drop into a column that was never dragged in is what gives its cards their ranks.

h3. redmine_expert_agile 0.2.0 — 2026-08-14

h4. Added

* *The backlog planner has the board's filter and options panel.* It was the one agile screen without one, so it always showed every open issue of the project and nothing you chose survived a page reload. It now carries Redmine's own filter widget, a collapsible *Options* fieldset for card fields and colouring, and Apply / Clear / Save, kept in the session so returning to the planner shows it as you left it. There are deliberately no status columns or WIP limits here: the planner ignores where an issue sits in the workflow, since an issue is either planned or it is not.
* *Saved backlogs.* A backlog can be saved, edited and deleted like a board or a chart, and saved backlogs are listed in the agile sidebar — which the backlog tab now shows at all. Saving needs the *Save agile boards* permission from the *expert Agile* module, so a project running only the *expert Agile Backlog* module can filter its backlog but not save one.
* *Backlog cards show the fields you select.* They were a fixed set of number, tracker, subject, status and story points; they now show the assignee and avatar, estimated hours, progress, the description excerpt and any selected column including custom fields, exactly as a board card does.

h4. Security

* *A saved board or backlog could be opened by anyone who knew its id.* Both lookups resolved the id straight from the table, so a private board belonging to another user opened for any member of the project — its name and its whole filter set, though never issue data, which Redmine's own issue visibility continued to enforce. Both now resolve through the visibility scope, and pin the query type so a board lookup cannot reach a saved chart or backlog gated on a different permission.
* *A saved board or backlog stayed open after it stopped being visible.* The session stores only an id and outlives the query it points at, so turning a shared board private, or removing the permission from a role, had no effect until the viewer's session happened to end. The session restore now checks visibility on every request and falls back to an unsaved board when the saved one is gone or no longer permitted.

h4. Fixed

* *A chart saved from its own screen was stored as a board.* The shared new/edit form hardcoded the board's routes, so every variant of the query controller posted to the board's. Where that form posts is now decided by the controller handling it.
* *"Show future data on charts" did nothing.* The setting was declared, documented and read, but no chart consulted it: series were drawn to the end of the selected range, so a burndown looked at mid-sprint ran flat to the sprint end and velocity showed empty buckets for weeks that had not happened. Measured series now stop at today unless the setting is on, while the ideal line — a projection, not a measurement — still spans the whole range.
* *Cumulative flow bands were indistinguishable.* Band colours were derived from each status's index among *all* statuses in the instance, so on an installation with many statuses a six-band chart drew six neighbouring shades of the same hue. The palette is now spread over the bands the chart actually draws.
* *Untranslated column header on the card colours screen.* The table header used a translation key neither this plugin nor Redmine defines, so the admin screen showed "Translation missing".

h4. Upgrade notes

No migrations. Replace the plugin directory and restart.

Saved backlogs reuse the existing *Save agile boards* and *Manage public agile boards* permissions, which live in the *expert Agile* module — no new permission to grant, but a project that has enabled *expert Agile Backlog* without *expert Agile* will be able to filter its backlog and not save it.

h3. redmine_expert_agile 0.1.0 — 2026-08-10

First release. Agile boards for Redmine, built on Redmine's own query system.

h4. Board

* Kanban board with columns from issue statuses, drag & drop between and within columns, swimlanes, and sub-column headers from a shared @Prefix:@ status naming.
* Advisory WIP limits — a column over its limit is flagged, the move is never blocked.
* Configurable card fields, card tooltips, and a project menu entry next to the Gantt chart.
* Boards are saved queries: every issue filter, column and visibility rule applies unchanged.

h4. Story points

* A story point value per issue, offered either as a configurable value list (modified Fibonacci by default) or as free numeric entry, and restrictable to selected trackers.
* Available on the issue form, in the issue attribute table, in bulk edit, and as a sortable column and filter on the issue list.
* Parent issues show the total across their subtree. "Not estimated" stays distinguishable from "estimated as zero".

h4. Sprints and backlog

* Sprints with start and end dates, an open/active/closed lifecycle and Version-style sharing across a project tree.
* Activating a sprint stands the project's other active sprint down; a sprint cannot be closed while it still holds open issues; overlapping sprints are rejected unless explicitly allowed.
* A backlog planner, behind its own project module, for dragging issues into sprints or versions.
* Sprint changes appear in the issue's own journal.

h4. Charts

Burndown, burnup, cumulative flow, velocity and cycle time, in issues, hours or story points, over day, week or month intervals. Chart.js is vendored with the plugin.

h4. Colours

Cards coloured by tracker, priority, status, project, assignee, spent time, or per issue, from a fixed palette chosen so card text stays readable.

h4. REST API

Agile data per issue is readable and writable, plus full sprint CRUD. See the API reference in the repository.

h4. Upgrade notes

New installation — three migrations create @expert_agile_data@, @expert_agile_sprints@ and @expert_agile_colors@. Run:

<pre>
bundle exec rake redmine:plugins:migrate NAME=redmine_expert_agile RAILS_ENV=production
</pre>

Enable the *expert Agile* module per project and grant the new permissions to your roles. If you also run RedmineUP's Agile plugin, do not enable both on the same project.
